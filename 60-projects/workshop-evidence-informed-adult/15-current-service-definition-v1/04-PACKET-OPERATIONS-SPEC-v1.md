# MFC packet operations specification v1

## Retrieval protocols

| Product/beat | Protocol |
|---|---|
| Introduction 31–41 | This is **guided recall/discrimination**, not unaided retrieval: facilitator prompts each process word and corrects collectively. |
| Introduction 57–60 | Before asking, hide/turn the `Stop–Shift–Do` visual. Say: “Take five quiet seconds. You may think privately, pass, or answer when ready: what are the three words?” After responses, re-show and state the correction: “Stop notices; Shift creates space or perspective when available; Do is an intentional next move.” Do not count responses. |
| Essentials 86–90 | Hide/turn visual and allow five silent seconds before collective answer. Re-show only after a pass/answer opportunity. Correct with the same three-sentence wording above. |
| Foundations 45–55 | No card/visual visible. Five quiet seconds, then private recall or pass. Only then show a neutral fictional card and ask for process application. The first part is unaided retrieval; card use is guided rehearsal. |
| Foundations 210–230 | No visual/card visible. Present only the opening line of a scenario, allow silent retrieval of the process, then reveal constraint text and work through discrimination. This is a second, context-distal unaided retrieval followed by guided discrimination. |

## Host preparation and accessibility record

Complete for every delivery candidate, without collecting participant health information: agenda available in advance; read-aloud/visual alternative; large-print/plain-text availability; language/interpreter requirement and competent provider; seating/quiet/pass route; sensory/movement needs; device-free delivery; mixed-seniority/pair-work caution; and named facilitator switch route. “No materials” means **no required participant worksheet, device, writing or data burden**; optional accessibility aids are permitted.

## Scenario selection record

For Essentials choose 2 IDs; for Foundations choose 3 IDs and one fallback. For Introduction use S5 unless its avoid/switch trigger is present, then use S1. Record: setting, chosen IDs, avoided IDs/reason, alternative scenario, live-conflict/grievance switch trigger, and whether paired work is suitable. If a scenario resembles a live dispute, stop and switch to the fallback without discussion.

| ID | Plain-text scenario | Read-aloud equivalent | Avoid/switch trigger |
|---|---|---|---|
| S1 Message | Stage 1: “A message changes a task you thought was settled.” Stage 2: “You are tired, unsure what it means, and feel the urge to reply immediately.” | Read each stage exactly when revealed. | identifiable recent message/incident |
| S2 Tension | Stage 1: “A comment is misunderstood in a conversation.” Stage 2: “The conversation becomes tense and other people are present.” | Read each stage exactly when revealed. | live team conflict |
| S3 Capacity | Stage 1: “A task is added when capacity is already stretched.” Stage 2: “The work cannot all be completed in the available time.” | Read each stage exactly when revealed. | prompts disclosure of workload dispute |
| S4 Speaking up | Stage 1: “A practical concern needs raising.” Stage 2: “The usual meeting is cancelled and there is a power difference.” | Read each stage exactly when revealed. | active grievance/disciplinary matter |
| S5 Public moment | Stage 1: “In a public place, someone reacts sharply.” Stage 2: “You notice tension and are unsure whether engaging is safe.” | Read each stage exactly when revealed. | threat/violence or culturally loaded incident |
| S6 Household | Stage 1: “A household conversation is tense.” Stage 2: “Everyone is tired and the situation does not feel ready to resolve.” | Read each stage exactly when revealed. | domestic safety concern |

All cards are delivered as the text above, on screen/large print/read aloud as needed. No hidden card asset is required.

## Foundations default deterministic selection record

For the frozen v1 core packet: **F06 (85–100) = S2**, **F07 (100–115) = S3**, **F10 (185–210) = S4 with Stage 1 then Stage 2 reveal**, fallback **S1**. A named-host tailoring record may replace these IDs only if it writes the same ordered mapping and fallback before the session; it may not alter the mechanism or switch rule.
